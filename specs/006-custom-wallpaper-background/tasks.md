# 006 - Scomposizione task

Un commit per task, Conventional Commits in inglese. Rollback `revert` = `git revert <sha>` del commit del task. Stime per uno sviluppatore che conosce il repo, buffer del 20% fuori dalle righe.

Regole comuni:

- test prima del codice: il `verify` è rosso sul commit di partenza e diventa verde col task;
- ogni asserzione negativa ("non chiama", "non copia", "non cancella") è appaiata a un caso positivo nello stesso test;
- ogni file nuovo entra nel blocco dimensionale di `eslint.config.js`; i file in `renderer/` sono già nel glob `renderer/settings*.js` di `coverage.include`;
- test su file system in una cartella temporanea (`fs.mkdtempSync(os.tmpdir())`) o con la HOME isolata come nei test esistenti di `wallpaper-changer-behavior`: nessun test tocca `~/.local/share/deadlineaura` o `~/.config/deadlineaura` reali;
- `npm test`, `npm run lint`, `npm run format:check` verdi; `npm run test:coverage` verde a fine T004, T007, T009.

Integrazioni dal security-reviewer (prevalgono sul testo delle righe della tabella):

- **T006**: dimensioni e formato letti dall'header prima di `loadImage` (vedi `plan.md` § Rilievi); `TOO_MANY_PIXELS` deciso sull'header. Ordine: `.tmp` orfano rimosso, copia su `.tmp` con modo `0o600`, `stat` + header + magic bytes + `loadImage` sul `.tmp`, `rename`. Verify aggiuntivi: fixture PNG reale con IHDR da 100000x100000 -> `TOO_MANY_PIXELS` senza che `loadImage` sia chiamato (spy), appaiata alla fixture piccola che lo chiama; GIF e SVG rinominati `.png` -> `UNREADABLE`, appaiati al PNG vero accettato; nessun `.tmp` rimasto dopo ogni errore. Il caso `loadImage` finto da 9000x5000 si toglie: non prova il limite.
- **T003/T004**: guardia header + `lstat` (niente symlink) anche nel percorso di render; esito negativo -> fallback D5 con il motivo nel log.
- **T007**: le risposte d'errore portano solo il codice; asserzione: nessun `/` nel payload d'errore.
