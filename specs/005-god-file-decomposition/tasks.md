# 005 - Scomposizione task

Un commit per task, Conventional Commits in inglese (`test(...)` per la rete, `refactor(...)` per gli spostamenti, `chore(...)` per lint e dipendenze). Rollback `revert` = `git revert <sha>` del commit del task: basta in tutti i casi, perché nessun task cambia dati persistenti o configurazione esterna. Stime per uno sviluppatore che non conosce il codice, buffer del 20% fuori dalle righe.

Regole comuni a ogni task che sposta codice:

- la rete del task (o della fase) è verde **prima** dello spostamento e il commit di spostamento non ne tocca le asserzioni (R2);
- ogni test nuovo su codice esistente si verifica rompendo il codice di proposito e vedendo il rosso, poi si ripristina (R3);
- il file nuovo entra nel blocco dimensionale di `eslint.config.js` (T002) e, se è in `renderer/`, in `coverage.include` e nell'ordine `<script>` della pagina, prima dello script che lo usa;
- le dipendenze da altri script del renderer passano come argomento (`t`, `api`, `ctx`), non come globali, così il modulo si richiede da Node senza setup;
- `npm test`, `npm run lint`, `npm run format:check` verdi; `npm run test:coverage` verde se il task tocca `coverage.include`.
