Regole comuni:

- un test di caratterizzazione vale solo se visto rosso: per ogni ramo nominato nel `verify` si applica a mano il mutante indicato, si osserva il test fallire, si ripristina. Il mutante non si committa;
- un test di regressione di un fix non si committa da solo (lascerebbe la suite rossa su `main`): test e fix vanno nello stesso commit `fix(...)`, con il rosso osservato prima del fix e riportato nel corpo del commit;
- ogni asserzione negativa ("non chiama", "nessun badge", "resta null") è appaiata a un caso positivo nello stesso test;
- test col DB reale nella HOME temporanea come `test/core/sync-daemon-scoring.test.js` (`vi.spyOn(os, 'homedir')`), mai sul DB vero;
- dopo ogni commit: `npm test`, `npx eslint .`, numero di test non in calo; `npm run test:coverage` a fine di ogni fase;
- un task di refactor che toglie un file da `ignores` in `eslint.config.js` ha come `verify` dimensionale: `npx eslint <file>` con errori sul commit di partenza (misurati: vedi colonna), zero a fine task.
